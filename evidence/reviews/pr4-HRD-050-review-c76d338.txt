2. BLOCKING
====================================================================================================
B1 (source-defect, data-safety surface 9.2 / 11.4.287 spirit; not minor-class per 11.4.276(G.2)):
   se_restore deletes / reverts files even when the backup copy FAILED, and it acts on any file that became dirty after the
   snapshot, including another agent's concurrent work in a shared checkout. Uncommitted work can be destroyed with rc 0.

   Code (tests/live/run_gated_tests.sh, se_restore):
     mkdir -p "$dest/$(dirname "$path")"; cp -- "$path" "$dest/$path"
     if [ "$st" = "??" ]; then rm -f -- "$path"; else git checkout -- "$path"; fi
   Neither mkdir nor cp is checked; `set -e` is not set; the rm/checkout runs regardless.

   Reproduction with the UNMUTATED gate's own --selftest-side-effects (scratch git repo, nothing of the operator's touched):
   (a) copy destination unwritable (stands in for ENOSPC/EACCES during a multi-hour run):
       snapshot; then "another writer" creates evidence/y/precious.txt and edits clean tracked evidence/y/t.txt;
       chmod 555 <before>.d ; restore:
         mkdir: Permission denied
         cp: cannot create regular file '.../b2.txt.d/evidence/y/t.txt': No such file or directory
         mkdir: Permission denied
         cp: cannot create regular file '.../b2.txt.d/evidence/y/precious.txt': No such file or directory
         restore2=0
       Result: evidence/y/ contains only t.txt with content "base"; precious.txt GONE; the "precious2" edit GONE;
       `find <before>.d -type f` -> nothing. Irreversible loss, reported as success (rc 0).
   (b) concurrent writer, normal disk: snapshot; another agent writes evidence/y/other_agent_new.txt and edits clean tracked
       evidence/y/agent_tracked.txt; restore -> other_agent_new.txt removed from its place, agent_tracked.txt reverted to
       "base"; content only survives under <OUT>/side_effects/. The runner defaults ROOT to the repository it lives in
       (the shared main worktree in this project) and runs for up to hours, so any other agent writing under evidence/
       during that window has its work silently moved away. The docs and PR body do not state this limit; the PR body's
       "only touches paths clean before the run" reads as a safety guarantee it is not.
   Minimum fix: copy-then-verify (cp && cmp) before rm/checkout, skip + report on any failure, non-zero/loud status; list every
   moved path in the run output; and either document "run only in a dedicated worktree" with a refusal when other writers
   are detected, or limit cleanup to files proven written by the run. Add a test with an unwritable/failed copy (a mutant
   removing the guard must die) and a test with a pre-existing untracked file inside an untracked directory (see I2).
