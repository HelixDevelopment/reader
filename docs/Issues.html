[HRD-027] Remove catalog and API scalability bottlenecks under measured enterprise loads

Status

In progress

Type

Task

Severity

Critical

Reopens

0

Description

Phase 1 landed: configurable catalog/AI-memory pools, distinct aimemory migration lock, durable scan records across restart, batched page child loads (measured 3.6x), and an additive keyset cursor through HTTP and OPDS with needle-proofed tests. First 50k-work measurements recorded in docs/scalability-review.md and evidence/campaign-2026-11-20/scalability/. DEFECT-003 (transport-contaminated and nondeterministic scale assertions) found and fixed. Identity locks are now scoped per work, edition and source instead of one global key: 5.85x write throughput in one process (271.94 -> 1592.21 ops/s) and 1.53x to 4.07x across separate OS processes, while the no-lock needle silently loses 8 of 480 concurrently merged editions (evidence/campaign-2026-11-20/lock-scope/ and .../multiprocess/). DEFECT-004: the multi-process needle was blind until a database barrier aligned process starts, because the unsafe window is only the first write to an identity that does not exist yet; the runner now refuses a run where the unlocked variant verifies clean. Concurrent read envelope measured at 1/8/32/64 clients with zero errors: indexed browse and OPDS plateau near 1000 req/s (repo) and 900 (HTTP), limited by database CPU rather than the pool (pool=64 probe 942 vs 992 req/s, zero pool waits), while unanchored %text% search plateaus near 9 req/s at p99 12.0 s with pool starvation stacked on that wall. Release gate still unmet: no ratified SLO, no ingest-concurrent-with-reads test, and content delivery, KOSync/Redis and remote-source connectors remain unmeasured under load. Vector search measured and fixed: Search carried the id tiebreak inside the ORDER BY distance clause, an ordering no pgvector index can satisfy, so every search scanned and sorted every stored embedding while the HNSW index was still maintained on insert (DEFECT-005). Moved outside the subquery: 28.3 ms -> 1.86 ms p50 and 172.8 -> 2748 req/s at 32 clients, 50k rows x 384 dims, and the index path is now chosen without being forced. The harness refuses to be trusted on its own word: catalog-level schema comparison, per-connection session attestation, and a cardinality-independent plan control, with a nine-mutation gate at 9/9 (evidence/campaign-2026-11-20/vector/). New open question, not a defect: hnsw.ef_search (compile-time default 40) is not configurable anywhere in the product, and recall@10 against an exhaustive scan of the same fixture is 0.1025 at that width on 384-dim uniform vectors, 0.5475 at width 400.

Affected scope

PostgreSQL writes and search, API pagination, job retention, and connection pools.

Reproduction / current observation

Measured and addressed: offset pagination (keyset cursor), per-work child-query fan-out (batched loads), catalog pool caps, and global write serialization, which is now one advisory lock per touched work/edition/source instead of one key for every writer (5.85x on disjoint concurrent merges in a single in-container run, at 89% of the unlocked ceiling; invariants carried by server/internal/catalog/lock_scope_test.go with paired needles and a key-class mutation gate). Vector search: fixed (DEFECT-005, 15.2x p50 at 50k rows, needle-gated harness). Still open: no ratified service-level objective, no recall or search-width objective for AI memory, no multi-process or multi-node topology result, unindexed text search and per-page count(*) deliberately unbudgeted, and same-content merges from distinct sources serialize by design.

Acceptance

Representative large-catalog benchmarks and load tests establish limits, durable queue behavior, and bounded query plans.

Closure criteria

Representative large-catalog benchmarks and load tests establish limits, durable queue behavior, and bounded query plans.
